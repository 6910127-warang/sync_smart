## 2: ปรับ Prototype ทั้ง 49 หน้าจอ (4 role) + shared assets ให้รองรับ Responsive เต็มรูปแบบ

- **ขอบเขตที่ทำงาน:** ทั้งหมด (scope ยืนยันแล้วจากผู้เรียกใช้งาน ไม่ต้องถามซ้ำ) — อัปเดต `prototype/assets/tokens.css`, `prototype/assets/components.css` (ใหม่: `prototype/assets/nav.js`) และหน้าจอ HTML ทั้ง 49 ไฟล์ (15 staff-hph, 16 pharmacist, 7 executive, 10 admin) บวก `prototype/index.html` ตาม DESIGN.md ที่อัปเดตแล้ว (§2.3, §3.1, §3.2, §3.3, §3.5, §3.6) — อ้างอิงมติที่บันทึกไว้ในลำดับที่ 1 ข้างต้น
- **assets/tokens.css:** อัปเดตคอมเมนต์อ้างอิง DESIGN.md เป็น 20260820, เอา `--container-min` (บังคับ desktop-only min-width เดิม) ออก, เพิ่มคอมเมนต์อธิบาย breakpoint (Mobile 320-767px / Tablet 768-1023px / Desktop 1024px+) — ค่าสี/ฟอนต์/spacing เดิมไม่เปลี่ยนแปลง
- **assets/components.css:** เขียนใหม่ทั้งไฟล์แบบ mobile-first (ฐาน = mobile, ขยายด้วย `min-width` media query ที่ 768px และ 1024px) ครอบคลุม: nav (`.sidebar` กลายเป็น off-canvas drawer พร้อม `.hamburger-btn`/`.drawer-scrim` ใหม่ คืนเป็น sidebar ซ้ายคงที่ที่ >=1024px), ปุ่ม (Primary/Danger เต็มความกว้างที่ < 768px), form (เพิ่ม `.form-grid-2col` responsive), ตาราง (`.data-table` แปลงเป็น card แนวตั้งที่ < 768px ผ่าน `data-label` + `::before`), KPI card grid (`.kpi-grid` 1/2/หลาย card ต่อแถวตาม breakpoint), modal (ปุ่มเรียงแนวตั้งที่ mobile)
- **assets/nav.js (ใหม่):** JS ขั้นต่ำสุดสำหรับ toggle เปิด/ปิด drawer เมนูเท่านั้น ไม่มี logic ทางธุรกิจ ผูกกับ 40 จาก 49 หน้าจอที่มี sidebar
- **หน้าจอที่แก้ไข:** ทุกไฟล์ 49 ไฟล์เพิ่ม viewport meta tag; 40 ไฟล์ที่มี sidebar เพิ่ม hamburger button + `.topbar-left` wrapper + `.drawer-scrim` + script include; 19 ไฟล์ที่มี `.data-table` เพิ่ม `data-label` ในทุก `<td>`; ย้าย inline `.kpi-grid`/`.filter-grid` ออกจาก `executive/dashboard.html`/`executive/report-filter.html` ไปใช้ shared class แทน; ปรับ `.login-card` ใน 4 ไฟล์ login.html เป็น responsive width; ปรับ `index.html` เป็น mobile-first — **ไม่มีการเปลี่ยนเนื้อหา/ฟีเจอร์/flow ของหน้าจอใดๆ** เปลี่ยนเฉพาะ layout/behavior ตาม breakpoint เท่านั้น ไม่มีการเพิ่ม/ลบหน้าจอหรือฟิลด์
- **prototype/screen-map.md:** เพิ่มหมายเหตุสถานะ Responsive ที่หัวไฟล์ และเพิ่ม changelog รอบ 5 อธิบายรายละเอียดการเปลี่ยนแปลงทั้งหมดข้างต้น
- **สิ่งที่ยังค้าง:** `prototype/consistency-check-log.md` (ดูแลโดย `/check-prototype-sync` เท่านั้น) ยังมี content hash เดิมของทุกหน้าจอ — เนื่องจากทุกไฟล์ถูกแก้ไข hash จะเปลี่ยนหมด ต้องรัน `/check-prototype-sync` รอบถัดไปเพื่อยืนยันว่าเนื้อหายังตรงกับ chain (คาดว่าจะผ่านเพราะไม่มีการเปลี่ยนเนื้อหา มีแต่ layout); ยังไม่มีการแก้ `01-requirements/02-feature-list.md` (FT-022 ระบุว่า "Desktop-first" ซึ่งตกยุคแล้วตามมติใหม่) เพราะไม่อยู่ในขอบเขตงานที่ได้รับมอบหมายรอบนี้ (เป็นหน้าที่ของ `feature-journey-builder`/`/check-backlog-sync`)

## 3: ตรวจสอบความสอดคล้อง Spec ↔ Backlog (backlog-sync-checker)

- **ขอบเขตที่ตรวจ:** อ่านครบทุกไฟล์ spec ใน `01-requirements/01-spec/` ทั้ง 6 ไฟล์ (001 ภาพรวมโครงการ, 002 เบิก-จ่ายยา NCD, 003 พยากรณ์สต็อก/แจ้งเตือน, 004 Dashboard, 005 เชื่อมต่อระบบเดิม, 006 RBAC/Security NFR) เทียบกับ `01-requirements/backlog.md` ทั้งไฟล์ (36 BL-ID)
- **สิ่งที่พบและแก้ไขแล้ว:** ไม่พบจุดที่ต้องแก้ไข — ตรวจ FR/US coverage ครบทุก FR/US ในทั้ง 6 spec (มี BL-ID รองรับครบ 100%), ตรวจ open items ของแต่ละ spec เทียบกับ `[รอยืนยัน]` flag ใน backlog (BL-009b, BL-019, BL-022, BL-023, BL-032 ยังคง flag ตรงกับ open item ที่ยังเปิดอยู่จริงในแต่ละ spec — ไม่มีจุดที่ resolved แล้วแต่ backlog ลืมปิด flag), ตรวจลิงก์ไฟล์ spec ทุกจุดในหมายเหตุ backlog ใช้งานได้ครบ, ตรวจ Epic mapping ตรงกับ spec ครบ 5 Epic — โดยเฉพาะยืนยัน **BL-026** ที่ถูกแก้ไขด้วยมือไปแล้วในช่วงเช้าของวันนี้ (Desktop-first → Responsive เต็มรูปแบบ, breakpoint mobile 320-767px/tablet 768-1023px/desktop 1024px+, `[รอยืนยัน]` ปิดแล้ว) สอดคล้องครบถ้วนกับทั้ง spec 001 (บรรทัด "แพลตฟอร์มเป้าหมาย") และ spec 006 (ตาราง NFR Usability + หัวข้อ "เพิ่มเติม 20260820") — เพิ่ม changelog บรรทัดใหม่ใน backlog.md บันทึกผลการตรวจรอบนี้
- **สิ่งที่ถามผู้ใช้และคำตอบ:** ไม่มี — ไม่พบจุดที่ต้องให้ผู้ใช้ตัดสินใจในรอบนี้
- **สิ่งที่ยังค้าง (ต้องตัดสินใจเพิ่ม):** พบความไม่สอดคล้อง**ภายใน spec 001 เอง** (ไม่ใช่ backlog sync issue): บรรทัด "แพลตฟอร์มเป้าหมาย" ในหัวข้อ "มุมมองผลิตภัณฑ์" ของ spec 001 ยังเขียนว่า "ดูรายละเอียด NFR และ breakpoint **ที่ยังไม่ยืนยัน**ใน [006]" ทั้งที่ spec 006 ยืนยัน breakpoint ไปแล้วในวันเดียวกัน (20260820) — backlog/BL-026 อ้างอิงค่าที่ถูกต้อง (ยืนยันแล้ว) อยู่แล้ว จึงไม่กระทบ backlog แต่ควรแก้ถ้อยคำใน spec 001 ให้ตรงกับ spec 006 ในโอกาสถัดไป (นอกขอบเขตของ agent นี้ที่แก้เฉพาะ backlog.md)
- **สรุป:** backlog อยู่ในสถานะ sync กับ spec ครบทุกไฟล์แล้ว (ไม่มีจุดค้างด้าน backlog — มีเพียงข้อสังเกตเรื่องถ้อยคำภายใน spec 001 ที่ควรพิจารณาแก้แยกต่างหาก)
