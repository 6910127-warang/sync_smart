## บริบท/ที่มา (Context)

Epic นี้คือแกนหลักของ SmartSync — ตอบ Root Cause ที่พบจากการสัมภาษณ์จริง (ดู [001](20260816-001-project-scope-and-problem-background.md)) ว่าผู้เบิก (เจ้าหน้าที่ รพ.สต.) และผู้คัดกรอง (เภสัชกร) ใช้เกณฑ์คำนวณยอดเบิกคนละมาตรฐานกัน โดยให้ระบบคำนวณยอดแนะนำเบิกจากสูตรเดียวกันแบบเรียลไทม์ แทนที่การใช้ดุลยพินิจแยกกัน

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** สร้างคำขอเบิก (ปกติ/ฉุกเฉิน), อนุมัติสองระดับ, ส่งออกไฟล์เพื่อจ่ายยา (เชื่อมกับ Epic 4), ยืนยันรับยา, ยอดคงคลัง real-time, audit trail, แจ้งเตือนก่อนถึงรอบเบิก
- **นอกขอบเขต:** การคำนวณเกณฑ์ safety stock เอง (ดู [003](20260816-003-stock-forecast-alerts.md)), กลไกไฟล์ Excel/INVC โดยละเอียด (ดู [005](20260816-005-legacy-system-integration.md))

## Functional Requirements

| ID | รายละเอียด |
|---|---|
| FR-1.1 | ระบบต้องคำนวณ**ยอดแนะนำสำหรับเบิก**ของแต่ละหน่วย/รายการยาในแต่ละเดือนโดยอัตโนมัติ จากเกณฑ์ safety stock (FR-2.1/FR-2.1b/FR-2.4 ใน [003](20260816-003-stock-forecast-alerts.md)) หักด้วยยอดคงเหลือปัจจุบันที่เจ้าหน้าที่ รพ.สต. รายงาน |
| FR-1.1a | ระบบต้องให้เจ้าหน้าที่ รพ.สต. กรอก**ยอดคงเหลือปัจจุบันของแต่ละรายการยา ณ วันที่สร้างคำขอ** (ใช้คำนวณ FR-1.1 และเป็นข้อมูลนำเข้าต่อเนื่องของ FR-2.1b) จากนั้นตรวจสอบ/ยืนยันยอดแนะนำที่ระบบคำนวณได้ เพื่อสร้างเป็นคำขอเบิกของเดือนนั้น |
| FR-1.1b | หากเจ้าหน้าที่ รพ.สต. ต้องการเปลี่ยนแปลงยอดแนะนำก่อนยืนยันคำขอ ระบบต้องมีปุ่ม**"ขอปรึกษา"** ซึ่งเมื่อกดแล้วต้องส่ง alert แจ้งกลุ่มเภสัชกรผ่าน LINE Official Account ที่มีอยู่แล้วทันที |
| FR-1.2 | ระบบต้องรองรับการอนุมัติคำขอเบิกแบบ **สองระดับ**: เภสัชกรผู้อนุมัติระดับ 1 พิจารณา/ปฏิเสธ/ปรับจำนวนก่อน จากนั้นเภสัชกรผู้ตรวจสอบระดับ 2 (คนละคนกับระดับ 1) ยืนยันซ้ำก่อนสถานะเปลี่ยนเป็น "อนุมัติแล้ว" |
| FR-1.3 | เมื่อคำขอได้รับการอนุมัติครบทั้งสองระดับ (FR-1.2) ระบบต้องเปลี่ยนสถานะคำขอเป็น "พร้อมส่งออก" — เภสัชกรผู้อนุมัติระดับ 2 กด **"คอนเฟิร์ม"** เพื่อสร้างไฟล์ Excel และส่งไปยังฝ่ายคลังยา รพ.แม่ข่าย (ดู [005](20260816-005-legacy-system-integration.md) FR-4.1/FR-4.1b) ทันทีที่กดคอนเฟิร์ม ระบบต้องเปลี่ยนสถานะเป็น **"จ่ายแล้ว"** โดยไม่ต้องรอการยืนยันย้อนกลับจากฝ่ายคลังยาว่านำเข้า INVC สำเร็จ — **เจ้าหน้าที่ รพ.สต. จะดาวน์โหลดไฟล์ Excel ได้ก็ต่อเมื่อเภสัชกรกดคอนเฟิร์มแล้วเท่านั้น** (ดาวน์โหลดไฟล์ล่าสุดที่ถูกคอนเฟิร์ม ไม่ใช่ก่อนหน้านั้น) |
| FR-1.4 | ระบบต้องให้เจ้าหน้าที่ รพ.สต. ยืนยันการรับยาเข้าคลังของหน่วยตนเอง |
| FR-1.5 | ระบบต้องคำนวณและแสดงยอดคงคลังของแต่ละหน่วยแบบ real-time หรือใกล้เคียง real-time หลังบันทึกรับ/จ่าย |
| FR-1.6 | ระบบต้องเก็บประวัติการเบิก-จ่าย-รับ ย้อนหลังเพื่อการตรวจสอบ (Audit trail) รวมถึงบันทึกผู้อนุมัติระดับ 1/2 ของแต่ละคำขอ และบันทึกทุกครั้งที่มีการกด "ขอปรึกษา" (FR-1.1b) |
| FR-1.7 | ระบบต้องให้เจ้าหน้าที่ รพ.สต. สร้างคำขอเบิกฉุกเฉินนอกรอบรายเดือนได้ (Off-cycle Requisition) โดยต้องผ่านการอนุมัติสองระดับเหมือนคำขอปกติ (FR-1.2) แต่กระบวนการอนุมัติควรเร็วขึ้นด้วยการแจ้งเตือนทันที (real-time notify) ไปยังผู้อนุมัติทั้งสองระดับ |
| FR-1.8 | ระบบต้องแจ้งเตือนเจ้าหน้าที่ รพ.สต. ล่วงหน้าก่อนถึงกำหนดส่งคำขอเบิกประจำเดือน เพื่อลดปัญหา**ลืมเบิกยา** ซึ่งเป็นสาเหตุหนึ่งของการเบิกด่วนนอกรอบ (ที่มา: Root Cause Analysis ใน [001](20260816-001-project-scope-and-problem-background.md)) `[ต้องยืนยัน — จำนวนวันล่วงหน้าที่ควรแจ้งเตือนก่อนถึงกำหนด]` |

## User Stories (Agile)

- **US-1.0** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการเห็นยอดแนะนำเบิกที่ระบบคำนวณให้อัตโนมัติ เพื่อไม่ต้องคำนวณจำนวนที่ต้องเบิกเองทุกเดือน

- **US-1.1** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการกรอกยอดคงเหลือปัจจุบันและยืนยันคำขอเบิกยา NCD ผ่านระบบ เพื่อลดความผิดพลาดจากการโทร/บันทึกใน Excel ด้วยมือ และเป็นข้อมูลให้ระบบคำนวณ safety stock ต่อเนื่อง
  - Acceptance Criteria:
    - [ ] Given เจ้าหน้าที่ รพ.สต. login เข้าระบบและเห็นยอดแนะนำเบิก, When กรอกยอดคงเหลือปัจจุบันของแต่ละรายการและกดยืนยันคำขอ, Then ระบบบันทึกคำขอสถานะ "รอการอนุมัติระดับ 1"

- **US-1.1b** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการกด "ขอปรึกษา" เมื่อไม่เห็นด้วยกับยอดแนะนำเบิก เพื่อให้กลุ่มเภสัชกรได้รับแจ้งเตือนผ่าน LINE OA และช่วยพิจารณาก่อนยืนยันคำขอ

- **US-1.2** ในฐานะ เภสัชกรผู้อนุมัติระดับ 1 ฉันต้องการเห็นคำขอเบิกทั้งหมดที่รอดำเนินการ เพื่อพิจารณาอนุมัติ/ปฏิเสธ/ปรับจำนวนได้อย่างรวดเร็ว

- **US-1.2b** ในฐานะ เภสัชกรผู้ตรวจสอบระดับ 2 ฉันต้องการเห็นคำขอที่ผ่านการอนุมัติระดับ 1 แล้ว เพื่อตรวจสอบซ้ำก่อนยืนยันให้จ่ายยาจริง
  - Acceptance Criteria:
    - [ ] Given คำขอผ่านการอนุมัติระดับ 1 แล้ว, When เภสัชกรระดับ 2 (คนละคนกับระดับ 1) กดยืนยัน, Then สถานะเปลี่ยนเป็น "อนุมัติแล้ว" และพร้อมบันทึกจ่าย
    - [ ] Given เภสัชกรคนเดียวกันเป็นผู้อนุมัติระดับ 1, When พยายามยืนยันระดับ 2 ของคำขอเดียวกัน, Then ระบบต้องปฏิเสธการกระทำ

- **US-1.3** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการยืนยันการรับยาในระบบ เพื่อให้ยอดคงคลังของหน่วยฉันถูกต้อง

- **US-1.4** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการสร้างคำขอเบิกฉุกเฉินนอกรอบรายเดือน เพื่อรับมือกรณียาหมดกะทันหันโดยไม่ต้องรอรอบเบิกถัดไป

- **US-1.5** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการได้รับแจ้งเตือนล่วงหน้าก่อนถึงกำหนดส่งคำขอเบิกประจำเดือน เพื่อลดปัญหาลืมเบิกยา

## คำถามที่ถามและคำตอบที่ได้ (Clarifications)

- **ถาม:** การอนุมัติคำขอเบิก ควรกำหนดอย่างไร? → **ตอบ:** ต้องมีการอนุมัติสองระดับ (Double-check)
- **ถาม:** การหมุนเวียนผู้อนุมัติระดับ 2 ควรเป็นแบบใด? → **ตอบ:** เลือกได้อิสระในทีมเภสัชกร ไม่ยึดเวรตายตัว
- **ถาม:** มีกรณีที่ต้องเบิกยานอกรอบรายเดือนหรือไม่? → **ตอบ:** มี ต้องรองรับการเบิกฉุกเฉินในระบบด้วย ผ่านอนุมัติสองระดับเหมือนคำขอปกติแต่เร็วขึ้นด้วย notify

## สิ่งที่ยังไม่ยืนยัน (Open Items)

- กระทบยอดคงเหลือที่แจ้งเอง (FR-1.1a) vs. ยอดคงคลังที่ระบบคำนวณอัตโนมัติ (FR-1.5) — ต้องมีการแจ้งเตือน/กระทบยอดหรือไม่
- ระยะเวลาแจ้งเตือนล่วงหน้าก่อนกำหนดเบิก (FR-1.8) — กี่วันก่อนถึงกำหนด
