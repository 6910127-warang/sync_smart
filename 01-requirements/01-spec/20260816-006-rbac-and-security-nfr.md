**Epic:** 5 (Cross-cutting — ใช้ร่วมกับทุก Epic)

> บริบทร่วม/stakeholder table เต็มดูที่ [001 — ภาพรวมโครงการ](20260816-001-project-scope-and-problem-background.md)

## บริบท/ที่มา (Context)

เอกสารนี้รวบรวมความต้องการที่ไม่ใช่เชิงฟังก์ชัน (NFR) และการควบคุมสิทธิ์การเข้าถึง (RBAC) ที่ใช้ร่วมกันทุก Epic แทนที่จะซ้ำในแต่ละไฟล์

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** RBAC ตาม role, Usability, Performance, Availability, PDPA, Compatibility กับ INVC, ช่องทางแจ้งเตือน
- **นอกขอบเขต:** รายละเอียด business logic ของแต่ละ Epic (ดูไฟล์ Epic นั้นๆ)

## Non-Functional Requirements

| หมวด | รายละเอียด |
|---|---|
| Usability | ใช้งานผ่านเว็บเบราว์เซอร์ทั่วไป ออกแบบเป็น **Desktop-first** เนื่องจากเจ้าหน้าที่ รพ.สต. ใช้งานผ่านคอมพิวเตอร์/โน้ตบุ๊กเป็นหลัก ไม่จำเป็นต้องรองรับแท็บเล็ต/มือถือแบบ responsive เต็มรูปแบบในเฟสนี้ ผู้ใช้ส่วนใหญ่ไม่ใช่สายเทคนิค ควรออกแบบ UI ให้เรียบง่าย |
| Security / สิทธิ์การเข้าถึง (RBAC) | ต้องแยกสิทธิ์ตาม Role อย่างชัดเจน: เจ้าหน้าที่ รพ.สต. เห็นเฉพาะหน่วยตนเอง, ผู้บริหาร Read-only + drill-down ทั้งเครือข่าย, Admin แก้ไขข้อมูลธุรกิจได้เฉพาะกรณีฉุกเฉินและต้องมี audit log ทุกครั้ง รวมถึงบังคับกฎ **ห้ามอนุมัติระดับ 1 และ 2 ด้วยเภสัชกรคนเดียวกัน** ในคำขอเดียวกัน (ดู [002](20260816-002-ncd-drug-requisition-core.md) FR-1.2) |
| Performance | เครือข่ายมี รพ.สต. 29 แห่ง + รพ.แม่ข่าย 1 แห่ง รวมผู้ใช้งานพร้อมกันคาดว่าไม่เกินหลักสิบราย ระบบควรตอบสนองการบันทึก/ดูยอดคงคลังภายในไม่กี่วินาที `[ต้องยืนยัน — เป้าหมาย response time ที่ชัดเจนหากมีข้อกำหนดเฉพาะ]` |
| Availability | `[ต้องยืนยัน — ระดับความพร้อมใช้งานที่ต้องการ เช่น รองรับการใช้งานในเวลาราชการเท่านั้น หรือ 24/7]` |
| Data Privacy / PDPA | ต้องมีมาตรการป้องกันข้อมูลตาม PDPA เนื่องจากเชื่อมโยงถึงข้อมูลการใช้ยาของผู้ป่วยทางอ้อม `[ต้องยืนยันระดับความเข้มงวดที่ต้องการ]` |
| Compatibility | ไฟล์ Excel ที่ส่งออก ([005](20260816-005-legacy-system-integration.md) FR-4.1) ต้องรองรับรูปแบบคอลัมน์ที่ INVC นำเข้าได้จริง (ดู FR-4.3) — ไม่ต้องพิจารณาความเข้ากันได้กับ HOSxP เนื่องจาก รพ.แม่ข่ายไม่ได้เชื่อม HIS หลักเข้ากับ INVC `[ต้องยืนยัน — รูปแบบคอลัมน์ที่แน่นอน]` |
| Notification Channel | การแจ้งเตือนสต็อกต่ำ ([003](20260816-003-stock-forecast-alerts.md) FR-2.3) และการแจ้ง "ขอปรึกษา" ([002](20260816-002-ncd-drug-requisition-core.md) FR-1.1b) ต้องส่งผ่าน**ทั้งอีเมลและ LINE** (LINE Official Account ที่มีอยู่แล้ว) |

## Functional Requirements

ไม่มี — Epic นี้เป็น NFR/cross-cutting concern ล้วน; RBAC ราย role โดยละเอียดอยู่ในตาราง stakeholder ที่ [001](20260816-001-project-scope-and-problem-background.md)

## User Stories (Agile)

ไม่มี user story เฉพาะ — RBAC และ NFR เป็นข้อกำหนดที่ผูกกับทุก user story ใน Epic 1-4 (เช่น "เห็นเฉพาะหน่วยตนเอง" ใน [002](20260816-002-ncd-drug-requisition-core.md), "drill-down" ใน [004](20260816-004-management-dashboard.md))

## คำถามที่ถามและคำตอบที่ได้ (Clarifications)

- **ถาม:** ผู้ดูแลระบบ (Admin) ควรมีสิทธิ์แก้ไขข้อมูลธุรกิจได้หรือไม่? → **ตอบ:** มีสิทธิ์แก้ไขข้อมูลธุรกิจได้ในกรณีฉุกเฉิน (ต้องบันทึก audit log ทุกครั้ง)
- **ถาม:** เจ้าหน้าที่ รพ.สต. ควรเห็นข้อมูลของหน่วยอื่นได้หรือไม่? → **ตอบ:** เห็นเฉพาะหน่วยตนเอง
- **ถาม:** อุปกรณ์ที่เจ้าหน้าที่ รพ.สต. ใช้งานหลัก? → **ตอบ:** คอมพิวเตอร์/โน้ตบุ๊ก (Desktop-first) ไม่ต้องรองรับ responsive เต็มรูปแบบ

## สิ่งที่ยังไม่ยืนยัน (Open Items)

- เป้าหมาย response time ที่ชัดเจนสำหรับ Performance
- ระดับความพร้อมใช้งาน (Availability) — เวลาราชการเท่านั้น หรือ 24/7
- ระดับความเข้มงวดของมาตรการ PDPA ที่ต้องการ
- รูปแบบคอลัมน์ที่แน่นอนของ INVC (ดูรายละเอียดเต็มใน [005](20260816-005-legacy-system-integration.md))
