## บริบท/ที่มา (Context)

เกณฑ์ safety stock ที่คำนวณในเอกสารนี้คือ input หลักของยอดแนะนำเบิกใน [002 — เบิก-จ่ายยา NCD (Core)](20260816-002-ncd-drug-requisition-core.md) FR-1.1 — เป็นกลไกที่ตอบ Root Cause โดยตรง (ดู [001](20260816-001-project-scope-and-problem-background.md)) คือทำให้ผู้เบิกและผู้คัดกรองเห็นตัวเลขจากสูตรเดียวกัน

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** คำนวณ safety stock เริ่มต้นจากข้อมูลย้อนหลัง, ปรับปรุงต่อเนื่องหลังใช้งานจริง, แจ้งเตือนสต็อกต่ำ, ปรับยอดคาดการณ์สำหรับเคสส่งต่อใหม่
- **นอกขอบเขต:** UI การกรอกยอดคงเหลือ (อยู่ใน [002](20260816-002-ncd-drug-requisition-core.md) FR-1.1a)

## Functional Requirements

| ID | รายละเอียด |
|---|---|
| FR-2.1 | **(ช่วงเริ่มต้นระบบ)** ระบบต้องคำนวณเกณฑ์ safety stock เริ่มต้นของแต่ละหน่วย/รายการยา จาก**อัตราการใช้เฉลี่ยย้อนหลังอย่างน้อย 3 ปี แบบเทียบช่วงเดือนเดียวกันของแต่ละปี (Year-over-year, same-month)** โดยใช้ข้อมูลประวัติจากกระบวนการเดิม (โทรศัพท์/Excel) ก่อนเริ่มใช้ SmartSync เช่น ค่าเฉลี่ยของเดือนมีนาคมคำนวณจากข้อมูลเดือนมีนาคมย้อนหลัง 3 ปีที่ผ่านมา ไม่ใช่ค่าเฉลี่ยแบบ rolling window ทั่วไป เพื่อรองรับความผันแปรตามฤดูกาล/รอบปี |
| FR-2.1b | **(หลังเริ่มใช้ระบบจริง)** ระบบต้องคำนวณ**ยอดใช้จริงของแต่ละเดือน**โดยอัตโนมัติจากข้อมูลที่เกิดขึ้นในการทำงานปกติ ไม่ต้องขอข้อมูลเพิ่มเติมจาก รพ.สต. อีก ตามสูตร: `ยอดใช้จริง = ยอดคงเหลือต้นเดือน + ยอดรับเข้าระหว่างเดือน (FR-1.4) − ยอดคงเหลือปลายเดือน` โดยยอดคงเหลือต้นเดือน/ปลายเดือน คือยอดคงเหลือที่เจ้าหน้าที่ รพ.สต. รายงานมาพร้อมคำขอเบิกของแต่ละรอบเดือน (FR-1.1a) จากนั้นนำยอดใช้จริงนี้ไปปรับปรุงการคำนวณ safety stock อย่างต่อเนื่องทุกเดือน แทนที่/เสริมข้อมูลย้อนหลังตาม FR-2.1 |
| FR-2.2 | ระบบต้องแจ้งเตือนเมื่อยอดคงคลังของหน่วยต่ำกว่าเกณฑ์ safety stock ที่คำนวณได้ตาม FR-2.1 |
| FR-2.3 | ระบบต้องแจ้งเตือนผ่าน**ทั้งอีเมลและ LINE** (LINE Official Account ที่มีอยู่แล้ว) |
| FR-2.4 | ระบบต้องให้**เภสัชกร รพ.แม่ข่าย** ระบุ**จำนวนคาดการณ์เพิ่มเติม (Manual Forecast Adjustment)** นอกเหนือจากค่าเฉลี่ยย้อนหลังตาม FR-2.1 ได้ ณ ขั้นตอนการพิจารณาอนุมัติคำขอเบิกแต่ละครั้ง (ระดับ 1) สำหรับกรณีที่ รพศ. ส่งต่อผู้ป่วยกลับไปรับยาเพิ่มที่ รพ.สต. เป็น**เคสใหม่** ซึ่งยังไม่มีข้อมูลย้อนหลังในหน่วยนั้น |

## User Stories (Agile)

- **US-2.1** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการได้รับแจ้งเตือนเมื่อยาใกล้หมด เพื่อเบิกยาทันเวลาก่อนยาขาด

- **US-2.2** ในฐานะ เภสัชกร รพ.แม่ข่าย ฉันต้องการเห็นแนวโน้มความต้องการยาของแต่ละหน่วยที่คำนวณจากข้อมูลย้อนหลังอย่างน้อย 3 ปีของเดือนเดียวกัน เพื่อวางแผนการจ่ายยาล่วงหน้าได้แม่นยำขึ้นตามฤดูกาล

- **US-2.3** ในฐานะ เภสัชกรผู้อนุมัติระดับ 1 ฉันต้องการระบุจำนวนคาดการณ์เพิ่มเติมขณะพิจารณาอนุมัติคำขอเบิกแต่ละครั้ง เมื่อมีการส่งต่อผู้ป่วยเคสใหม่จาก รพศ. ไปรับยาที่ รพ.สต. เพื่อให้เกณฑ์ safety stock ของหน่วยนั้นสะท้อนความต้องการจริงแม้ยังไม่มีข้อมูลย้อนหลัง
  - Acceptance Criteria:
    - [ ] Given เภสัชกรผู้อนุมัติระดับ 1 กำลังพิจารณาคำขอเบิก, When ระบุจำนวนคาดการณ์เพิ่มเติมสำหรับเคสใหม่, Then ระบบบวกจำนวนนี้เข้ากับเกณฑ์ safety stock ที่คำนวณจาก FR-2.1 สำหรับหน่วยนั้น

## คำถามที่ถามและคำตอบที่ได้ (Clarifications)

- **ถาม:** เกณฑ์แจ้งเตือนสต็อกต่ำ (safety stock) ควรคำนวณอย่างไร? → **ตอบ:** คำนวณจากอัตราการใช้เฉลี่ยย้อนหลัง อย่างน้อย 3 ปี โดยคิดจากช่วงเดือนนั้นๆ ในแต่ละปี (year-over-year)
- **ถาม:** หลังเริ่มใช้ระบบจริง ยังต้องขอข้อมูลย้อนหลังเพิ่มไหม? → **ตอบ:** ไม่ต้อง — ยอดใช้จริงคำนวณอัตโนมัติจากยอดคงเหลือต้น/ปลายเดือนที่ รพ.สต. รายงานมาพร้อมคำขอเบิกอยู่แล้ว (สูตร stock-flow)
- **ถาม:** ใครระบุจำนวนคาดการณ์เพิ่มเติมสำหรับเคสใหม่ และเมื่อไร? → **ตอบ:** เภสัชกร รพ.แม่ข่าย ระบุตอนสร้าง/พิจารณาคำขอเบิกแต่ละครั้ง
- **ถาม:** ช่องทางแจ้งเตือนที่ต้องการ? → **ตอบ:** ทั้ง 2 ช่องทาง อีเมล/LINE
