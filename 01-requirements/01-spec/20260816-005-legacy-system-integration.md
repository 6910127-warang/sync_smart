# เชื่อมต่อกับระบบเดิม (JHCIS/myPCU ที่ รพ.สต. และ INVC ที่ รพ.แม่ข่าย)

**Spec ID:** 20260816-005
**สถานะ:** Migrated (ย้ายจาก `docs/requirements/REQUIREMENTS.md` ฉบับก่อนปรับโครงสร้างเอกสาร)
**วันที่สร้าง:** 20260816
**Epic:** 4 (ลำดับความสำคัญต่ำสุดใน 4 Epic แต่มีความไม่แน่นอนสูงสุด)

> บริบทร่วม/glossary ดูที่ [001 — ภาพรวมโครงการ](20260816-001-project-scope-and-problem-background.md) — โดยเฉพาะนิยามของ INVC และ JHCIS/myPCU

## บริบท/ที่มา (Context)

รพ.สต. ทั้ง 29 แห่งในเครือข่ายใช้**ทั้ง JHCIS และ myPCU**; รพ.แม่ข่ายใช้ **INVC** (โปรแกรมคลังยาที่พัฒนาเอง แจกจ่ายเกือบทั่วประเทศ) — **ไม่ใช่ HOSxP** และรพ.แม่ข่ายไม่ได้เชื่อม HIS หลักกับ INVC เลย จึงตัด HOSxP ออกจากขอบเขตนี้ทั้งหมด

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** สร้างไฟล์ Excel คำขอเบิกอัตโนมัติ, ช่องทางส่งไฟล์ไปฝ่ายคลังยา รพ.แม่ข่าย, รูปแบบไฟล์ให้ตรงกับ INVC
- **นอกขอบเขต (เฟสนี้):** การเชื่อมต่อ API/real-time กับ INVC หรือ JHCIS/myPCU โดยตรง — ใช้วิธีนำเข้า/ส่งออกไฟล์ (Manual batch) เท่านั้น

## Functional Requirements

| ID | รายละเอียด |
|---|---|
| FR-4.1 | ระบบต้องให้**เภสัชกรผู้อนุมัติระดับ 2** กด**"คอนเฟิร์ม"**บนหน้าจอโปรแกรม เมื่อคำขออยู่ในสถานะ "พร้อมส่งออก" (ดู [002](20260816-002-ncd-drug-requisition-core.md) FR-1.3) เพื่อสร้าง**ไฟล์ Excel คำขอเบิก**และส่งเข้าอีเมล + แจ้งเตือนผ่าน LINE OA ไปยังฝ่ายคลังยา รพ.แม่ข่าย ในขั้นตอนเดียว — ทันทีที่กดคอนเฟิร์ม ระบบต้องเปลี่ยนสถานะคำขอเป็น "จ่ายแล้ว" |
| FR-4.1b | ระบบต้องให้**เจ้าหน้าที่ รพ.สต.** (ผู้สร้างคำขอเดิม) ดาวน์โหลดไฟล์ Excel เดียวกันกับที่ถูกส่งใน FR-4.1 ได้ เพื่อเก็บไว้เป็นสำเนาของหน่วยตนเอง — **ดาวน์โหลดได้ก็ต่อเมื่อเภสัชกรกดคอนเฟิร์มแล้วเท่านั้น** (ก่อนหน้านั้นยังดาวน์โหลดไม่ได้ แม้คำขอจะอยู่ในสถานะ "พร้อมส่งออก" แล้วก็ตาม) |
| FR-4.2 | ช่องทางส่งไฟล์ตาม FR-4.1 คือ**อีเมลและ LINE OA** (LINE Official Account ที่มีอยู่แล้ว) ไปยังฝ่ายคลังยา รพ.แม่ข่าย เพื่อให้ฝ่ายคลังยานำไฟล์ไปนำเข้า **INVC เอง** (นอกระบบ SmartSync) สำหรับตัดคลังและจัดยา |
| FR-4.3 | **(ยืนยันแล้ว 20260823)** ระบบต้องสร้างไฟล์ Excel คำขอเบิกให้ตรงกับรูปแบบที่ INVC รับนำเข้าได้ทันทีโดยไม่ต้องแปลงเพิ่มเติม — ยืนยันจากไฟล์ตัวอย่างจริง 46 ไฟล์ (ครอบคลุมทั้ง 29 หน่วยในเครือข่าย รวมเรือนจำ) ที่เจ้าของข้อกำหนดตรวจสอบเองว่าเป็น target format ของ INVC จริง ไม่ใช่ไฟล์จากระบบอื่นที่ต้องแปลงก่อน: (1) รูปแบบไฟล์ Excel 97-2003 (`.xls`), 1 ไฟล์ต่อหน่วยต่อรอบเบิก, 1 sheet ต่อไฟล์ (ชื่อ sheet = ชื่อหน่วย), แถวแรกเป็น header, ไม่มี merge cell/format พิเศษ (2) มี 3 คอลัมน์เท่านั้น เรียงลำดับตายตัวดังนี้: **`HOSP_CODE`** (ข้อความ 4-6 ตัวอักษร, รหัสยาเฉพาะของหน่วย/รพ. เช่น AMOXT2/PARAT2, **อนุญาตให้ว่างได้** — พบว่าว่าง ~4.3% ของแถวในไฟล์ตัวอย่าง เป็นกรณีปกติไม่ใช่ข้อผิดพลาด), **`QTY_DISP`** (ตัวเลขจำนวนเต็ม, **ห้ามว่าง**, ความหมายคือ "จำนวนที่ขอเบิก" = ยอดที่อนุมัติจริงหลังผ่านอนุมัติ 2 ระดับ ตาม [002](20260816-002-ncd-drug-requisition-core.md) FR-1.2 — ชื่อคอลัมน์สื่อว่า dispensed แต่ในบริบทนี้ไม่ใช่จำนวนที่จ่ายจริง), **`WORKING_CODE`** (ตัวเลข 7 หลัก เก็บเป็นข้อความ, รหัสยามาตรฐาน, **ห้ามว่างและห้ามซ้ำภายในไฟล์เดียวกัน** — เป็น**คีย์หลักที่ระบบต้องใช้ผูกกับรายการยาในระบบ SmartSync** แทน `HOSP_CODE` เนื่องจาก `HOSP_CODE` ว่างได้) |
| FR-4.3a | **(ใหม่ 20260823)** ระบบต้องสร้างไฟล์แยกเป็น**2 ชุดต่อหน่วยต่อรอบเบิก**เมื่อคำขอเบิกของหน่วยนั้นมีรายการยาหมวด "บัญชีแพทย์" อย่างน้อย 1 รายการ: **`ใบเบิกยา{ชื่อหน่วย}.xls`** สำหรับรายการยาปกติ (ทุกหน่วยมีไฟล์นี้เสมออย่างน้อย 1 ไฟล์ต่อรอบ) และ **`ใบเบิกยาบัญชีแพทย์{ชื่อหน่วย}.xls`** สำหรับรายการยาบัญชีแพทย์เท่านั้น (สร้างเฉพาะหน่วยที่มีแพทย์ไปออกตรวจจริงและมีรายการยาประเภทนี้ในคำขอนั้น — ไม่ใช่ทุกหน่วย) ทั้งสองไฟล์ (เมื่อมีทั้งคู่) ใช้โครงสร้างคอลัมน์เดียวกันตาม FR-4.3 ทุกประการ ต่างกันเฉพาะรายการยาที่บรรจุอยู่ภายใน และต้องถูกส่ง (FR-4.2) + เปิดให้ดาวน์โหลด (FR-4.1b) พร้อมกันในขั้นตอนคอนเฟิร์มเดียวกัน (FR-4.1) ไม่ใช่คนละรอบ — `[ถือว่า]` ยึดชื่อไฟล์ตามรูปแบบที่เจ้าของข้อกำหนดอธิบาย (`ใบเบิกยาบัญชีแพทย์{ชื่อหน่วย}.xls`) เป็นรูปแบบมาตรฐาน แม้ในไฟล์ตัวอย่างจริงจะพบ 1 ไฟล์ (`ใบเบิกบัญชีแพทย์หัวฝาย.xls`) ที่ขาดคำว่า "ยา" ไปเมื่อเทียบกับอีก 21 ไฟล์บัญชีแพทย์ที่เหลือ — ถือว่าเป็นความคลาดเคลื่อนของไฟล์ตัวอย่างไฟล์เดียว ไม่ใช่กติกาการตั้งชื่อที่ตั้งใจ |
| FR-4.3b | **(ใหม่ 20260823, ข้อกำหนดเชิงข้อมูลรองรับ FR-4.3a)** ระบบต้องมีข้อมูลเพียงพอที่จะระบุได้ว่ารายการยา (Drug/Item Master) รายการใดจัดอยู่ในหมวด "บัญชีแพทย์" (คนละหมวดจากยาปกติ) เพื่อใช้ตัดสินใจแยกไฟล์ตาม FR-4.3a — รายละเอียดรูปแบบข้อมูล (field/flag) ที่แน่นอนให้เป็นไปตามการปรับปรุง [06-data-model.md](../06-data-model.md) หมวด "รายการยา (Drug/Item Master)" ผ่าน `/build-data-api-spec` รอบถัดไป ([ดูเหตุผลการ defer ในหัวข้อ "เพิ่มเติม 20260823" ด้านล่าง]) |
| FR-4.4 | **(ยืนยันแล้ว 20260823)** ระบบไม่จำเป็นต้องแลกเปลี่ยนข้อมูลกับ JHCIS/myPCU ของ รพ.สต. โดยตรงในเฟสนี้ เนื่องจากข้อมูลยอดคงเหลือ/การเบิกได้มาจากการกรอกในระบบ SmartSync เอง ([002](20260816-002-ncd-drug-requisition-core.md) FR-1.1a) ไม่ใช่ดึงจาก JHCIS/myPCU |
| FR-4.4a | **(ใหม่ 20260823, รายละเอียดเชิงปฏิบัติการ ไม่ใช่การเชื่อมต่อระบบ)** ในขั้นเริ่มต้นของโครงการ (one-off setup) ทีมงานจะขอ**ไฟล์ข้อมูลการจ่ายยาย้อนหลังอย่างน้อย 3 ปีจาก รพ.สต. ทุกแห่ง (29 แห่ง)** ผ่านการประสานงาน/ขอไฟล์ด้วยมือโดยตรงกับแต่ละหน่วย — **ไม่ใช่การเชื่อมต่อ API/ระบบกับ JHCIS/myPCU โดยอัตโนมัติ** (ยังคงสอดคล้องกับข้อสรุปของ FR-4.4 ด้านบนที่ไม่เชื่อมต่อโดยตรงในเฟสนี้) ไฟล์ข้อมูลชุดนี้เป็นฐานคำนวณ safety stock เริ่มต้นตาม [003](20260816-003-stock-forecast-alerts.md) FR-2.1 และเป็นงานตั้งต้นเดียวกับที่ระบุใน [003](20260816-003-stock-forecast-alerts.md) FT-009/BL-010 — รูปแบบไฟล์/โครงสร้างข้อมูลที่แท้จริงของ JHCIS/myPCU **ยังไม่ต้องยืนยัน** เนื่องจากเป็นการส่งมอบไฟล์ด้วยมือ ไม่ใช่การอ่านข้อมูลจากระบบนั้นโดยตรง |

## User Stories (Agile)

- **US-4.1** ในฐานะ เภสัชกรผู้อนุมัติระดับ 2 ฉันต้องการกด "คอนเฟิร์ม" เมื่อคำขออยู่ในสถานะ "พร้อมส่งออก" เพื่อสร้างไฟล์ Excel คำขอเบิกและส่งเข้าอีเมล + แจ้งเตือน LINE OA ไปยังฝ่ายคลังยา รพ.แม่ข่าย และให้ระบบบันทึกว่าจ่ายยาแล้ว
  - Acceptance Criteria:
    - [ ] Given คำขอมีสถานะ "พร้อมส่งออก", When เภสัชกรผู้อนุมัติระดับ 2 กด "คอนเฟิร์ม", Then ระบบสร้างไฟล์ Excel และส่งเข้าอีเมล + LINE OA ไปยังฝ่ายคลังยา รพ.แม่ข่าย และเปลี่ยนสถานะคำขอเป็น "จ่ายแล้ว" ทันที

- **US-4.1b** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการดาวน์โหลดไฟล์ Excel คำขอเบิกที่เภสัชกรกดคอนเฟิร์มแล้ว เพื่อเก็บไว้เป็นสำเนาของหน่วยตนเอง
  - Acceptance Criteria:
    - [ ] Given เภสัชกรยังไม่ได้กดคอนเฟิร์ม, When เจ้าหน้าที่ รพ.สต. พยายามดาวน์โหลดไฟล์, Then ระบบต้องไม่ให้ดาวน์โหลด
    - [ ] Given เภสัชกรกดคอนเฟิร์มแล้ว, When เจ้าหน้าที่ รพ.สต. เข้ามาดาวน์โหลด, Then ได้ไฟล์ Excel ฉบับที่ถูกคอนเฟิร์มล่าสุด

- **US-4.2** ในฐานะ ฝ่ายคลังยา รพ.แม่ข่าย ฉันต้องการรับไฟล์ Excel คำขอเบิกที่มีรูปแบบตรงกับที่ INVC นำเข้าได้ เพื่อไม่ต้องคีย์ข้อมูลซ้ำก่อนตัดคลัง
  - Acceptance Criteria:
    - [ ] Given คำขอผ่านการคอนเฟิร์มแล้ว (FR-4.1), When ระบบสร้างไฟล์ Excel, Then ไฟล์เป็น `.xls` (Excel 97-2003), 1 sheet ต่อไฟล์ชื่อ sheet ตรงกับชื่อหน่วย, แถวแรกเป็น header, ไม่มี merge cell/format พิเศษ, มี 3 คอลัมน์เรียงลำดับ `HOSP_CODE`, `QTY_DISP`, `WORKING_CODE` เท่านั้น
    - [ ] Given มีรายการยาที่ `HOSP_CODE` ว่าง, When ระบบสร้างไฟล์, Then ระบบต้องไม่ปฏิเสธ/error แถวนั้น (ค่าว่างเป็นกรณีปกติ)
    - [ ] Given ระบบสร้างไฟล์สำเร็จ, When ตรวจสอบคอลัมน์ `QTY_DISP` และ `WORKING_CODE` ของทุกแถวในไฟล์, Then ทั้งสองคอลัมน์ต้องไม่มีค่าว่างเลยแม้แต่แถวเดียว และค่า `WORKING_CODE` ต้องไม่ซ้ำกันภายในไฟล์เดียวกัน — **(ยืนยันแล้ว 20260823)** กลไกป้องกันที่ต้นทางคือการบังคับที่ operation "เพิ่ม/แก้ไขรายการยา" ([07-api-spec.md](../07-api-spec.md) หมวดรายการยา) ให้ `WORKING_CODE` เป็นฟิลด์จำเป็น+unique ที่ระดับ entity ของ DrugItem ([06-data-model.md](../06-data-model.md) หมวด "รายการยา") ไม่ใช่การตรวจตอน generate ไฟล์ export
    - [ ] Given คำขอของหน่วยหนึ่งมีทั้งรายการยาปกติและรายการยาบัญชีแพทย์ (FR-4.3a), When ระบบสร้างไฟล์, Then ได้ไฟล์ 2 ไฟล์แยกกัน (`ใบเบิกยา{ชื่อหน่วย}.xls` และ `ใบเบิกยาบัญชีแพทย์{ชื่อหน่วย}.xls`) โดยแต่ละไฟล์มีเฉพาะรายการยาของหมวดตนเอง
    - [ ] Given คำขอของหน่วยหนึ่งไม่มีรายการยาบัญชีแพทย์เลย, When ระบบสร้างไฟล์, Then ได้เฉพาะ `ใบเบิกยา{ชื่อหน่วย}.xls` ไฟล์เดียว ไม่สร้างไฟล์บัญชีแพทย์เปล่า

## คำถามที่ถามและคำตอบที่ได้ (Clarifications)

- **ถาม:** รพ.สต. ในเครือข่ายใช้ระบบอะไร, รพ.แม่ข่ายใช้ระบบอะไร? → **ตอบ:** รพ.สต. 29 แห่งใช้ JHCIS และ myPCU (ทั้งสองระบบ); รพ.แม่ข่ายใช้ INVC (ไม่ใช่ HOSxP, ไม่เชื่อม HIS หลักกับ INVC)
- **ถาม:** ต้องการรูปแบบการเชื่อมต่อแบบใด? → **ตอบ:** นำเข้า/ส่งออกไฟล์ (Manual batch) — ระบบคำนวณยอดเบิก → generate Excel อัตโนมัติ → ส่งให้ รพศ. → ฝ่ายคลังยานำเข้า INVC เองเพื่อตัดคลัง
- **ถาม (20260816):** ขั้นตอน "กดปุ่ม → คำนวณอัตโนมัติ → ไฟล์ Excel" เกิดขึ้นตอนไหนเทียบกับ flow ที่มีอยู่? → **ตอบ:** หลังอนุมัติครบ 2 ระดับ แต่คนที่กด "คอนเฟิร์ม" ส่งไฟล์จริงคือเภสัชกรผู้อนุมัติระดับ 2 ไม่ใช่ จนท. รพ.สต.
- **ถาม (20260816):** ไฟล์ที่ส่งเข้าอีเมล + LINE OA ส่งไปหาใคร? → **ตอบ:** ฝ่ายคลังยา รพ.แม่ข่าย (ตาม FR-4.2 เดิม) — **ช่องทางนี้ resolved แล้ว**

`backlog-sync-checker` ตรวจพบว่า Open Items 2 รายการที่เปิดไว้เมื่อ 20260823 (ตอนยืนยัน FR-4.3/4.3a/4.3b) ที่จริงถูกปิดไปแล้วในรอบต่อๆ มาของวันเดียวกัน แต่ข้อความในไฟล์นี้ไม่เคยถูกอัปเดตให้ตรงกัน จึงแก้ไขให้ตรงกับความจริงบนดิสก์ (ไม่ใช่การตัดสินใจใหม่):

- US-4.2 AC ข้อ "กลไกป้องกันที่ต้นทาง" (`[รอยืนยัน]`) → ปิดแล้ว: บังคับที่ operation "เพิ่ม/แก้ไขรายการยา" ให้ `WORKING_CODE` จำเป็น+unique ที่ระดับ entity ([06-data-model.md](../06-data-model.md) หมวด "รายการยา")
- Open Item "ต้องเพิ่มฟิลด์/flag ในรายการยา" → ปิดแล้ว: เพิ่มครบทั้ง `WORKING_CODE`/`HOSP_CODE`/flag "หมวดบัญชีแพทย์" ผ่าน `/build-data-api-spec` แล้ว (รวมยืนยันรูปแบบ flag ผ่าน `AskUserQuestion` แล้วด้วย)
- Open Item "FT-018/detailed-design ยังมีหมายเหตุบล็อกค้างอยู่" → ปิดแล้ว: อัปเดตผ่าน `/check-backlog-sync` และ `/build-detailed-design FT-018` แล้ว
