# เชื่อมต่อกับระบบเดิม (JHCIS/myPCU ที่ รพ.สต. และ INVC ที่ รพ.แม่ข่าย)

**Spec ID:** 20260816-005
**สถานะ:** Migrated (ย้ายจาก `docs/requirements/REQUIREMENTS.md` ฉบับก่อนปรับโครงสร้างเอกสาร)
**วันที่สร้าง:** 20260816
**Epic:** 4 (ลำดับความสำคัญต่ำสุดใน 4 Epic แต่มีความไม่แน่นอนสูงสุด)

> บริบทร่วม/glossary ดูที่ [001 — ภาพรวมโครงการ](20260816-001-project-scope-and-problem-background.md) — โดยเฉพาะนิยามของ INVC และ JHCIS/myPCU

## บริบท/ที่มา (Context)

รพ.สต. ทั้ง 29 แห่งในเครือข่ายใช้**ทั้ง JHCIS และ myPCU**; รพ.แม่ข่ายใช้ **INVC** (โปรแกรมคลังยาที่พัฒนาเอง แจกจ่ายเกือบทั่วประเทศ) — **ไม่ใช่ HOSxP** และรพ.แม่ข่ายไม่ได้เชื่อม HIS หลักกับ INVC เลย จึงตัด HOSxP ออกจากขอบเขตนี้ทั้งหมด

## ขอบเขต (Scope)

- **อยู่ในขอบเขต:** สร้างไฟล์ Excel คำขอเบิกอัตโนมัติ, ช่องทางส่งไฟล์ไปฝ่ายคลังยา รพ.แม่ข่าย, รูปแบบไฟล์ให้ตรงกับ INVC
- **นอกขอบเขต (เฟสนี้):** การเชื่อมต่อ API/real-time กับ INVC หรือ JHCIS/myPCU โดยตรง — ใช้วิธีนำเข้า/ส่งออกไฟล์ (Manual batch) เท่านั้น

## Functional Requirements

| ID | รายละเอียด |
|---|---|
| FR-4.1 | ระบบต้องให้**เภสัชกรผู้อนุมัติระดับ 2** กด**"คอนเฟิร์ม"**บนหน้าจอโปรแกรม เมื่อคำขออยู่ในสถานะ "พร้อมส่งออก" (ดู [002](20260816-002-ncd-drug-requisition-core.md) FR-1.3) เพื่อสร้าง**ไฟล์ Excel คำขอเบิก**และส่งเข้าอีเมล + แจ้งเตือนผ่าน LINE OA ไปยังฝ่ายคลังยา รพ.แม่ข่าย ในขั้นตอนเดียว — ทันทีที่กดคอนเฟิร์ม ระบบต้องเปลี่ยนสถานะคำขอเป็น "จ่ายแล้ว" |
| FR-4.1b | ระบบต้องให้**เจ้าหน้าที่ รพ.สต.** (ผู้สร้างคำขอเดิม) ดาวน์โหลดไฟล์ Excel เดียวกันกับที่ถูกส่งใน FR-4.1 ได้ เพื่อเก็บไว้เป็นสำเนาของหน่วยตนเอง — **ดาวน์โหลดได้ก็ต่อเมื่อเภสัชกรกดคอนเฟิร์มแล้วเท่านั้น** (ก่อนหน้านั้นยังดาวน์โหลดไม่ได้ แม้คำขอจะอยู่ในสถานะ "พร้อมส่งออก" แล้วก็ตาม) |
| FR-4.2 | ช่องทางส่งไฟล์ตาม FR-4.1 คือ**อีเมลและ LINE OA** (LINE Official Account ที่มีอยู่แล้ว) ไปยังฝ่ายคลังยา รพ.แม่ข่าย เพื่อให้ฝ่ายคลังยานำไฟล์ไปนำเข้า **INVC เอง** (นอกระบบ SmartSync) สำหรับตัดคลังและจัดยา |
| FR-4.3 | ระบบต้องรองรับรูปแบบไฟล์/โครงสร้างคอลัมน์ที่ตรงกับที่ INVC รองรับการนำเข้า `[ต้องยืนยัน — บล็อกการพัฒนา — รูปแบบคอลัมน์ที่แน่นอนของ INVC]` |
| FR-4.4 | ระบบไม่จำเป็นต้องแลกเปลี่ยนข้อมูลกับ JHCIS/myPCU ของ รพ.สต. โดยตรงในเฟสนี้ เนื่องจากข้อมูลยอดคงเหลือ/การเบิกได้มาจากการกรอกในระบบ SmartSync เอง ([002](20260816-002-ncd-drug-requisition-core.md) FR-1.1a) ไม่ใช่ดึงจาก JHCIS/myPCU `[ต้องยืนยัน — ยืนยันว่าไม่ต้องเชื่อมต่อกับ JHCIS/myPCU เลยในเฟสนี้]` |

## User Stories (Agile)

- **US-4.1** ในฐานะ เภสัชกรผู้อนุมัติระดับ 2 ฉันต้องการกด "คอนเฟิร์ม" เมื่อคำขออยู่ในสถานะ "พร้อมส่งออก" เพื่อสร้างไฟล์ Excel คำขอเบิกและส่งเข้าอีเมล + แจ้งเตือน LINE OA ไปยังฝ่ายคลังยา รพ.แม่ข่าย และให้ระบบบันทึกว่าจ่ายยาแล้ว
  - Acceptance Criteria:
    - [ ] Given คำขอมีสถานะ "พร้อมส่งออก", When เภสัชกรผู้อนุมัติระดับ 2 กด "คอนเฟิร์ม", Then ระบบสร้างไฟล์ Excel และส่งเข้าอีเมล + LINE OA ไปยังฝ่ายคลังยา รพ.แม่ข่าย และเปลี่ยนสถานะคำขอเป็น "จ่ายแล้ว" ทันที

- **US-4.1b** ในฐานะ เจ้าหน้าที่ รพ.สต. ฉันต้องการดาวน์โหลดไฟล์ Excel คำขอเบิกที่เภสัชกรกดคอนเฟิร์มแล้ว เพื่อเก็บไว้เป็นสำเนาของหน่วยตนเอง
  - Acceptance Criteria:
    - [ ] Given เภสัชกรยังไม่ได้กดคอนเฟิร์ม, When เจ้าหน้าที่ รพ.สต. พยายามดาวน์โหลดไฟล์, Then ระบบต้องไม่ให้ดาวน์โหลด
    - [ ] Given เภสัชกรกดคอนเฟิร์มแล้ว, When เจ้าหน้าที่ รพ.สต. เข้ามาดาวน์โหลด, Then ได้ไฟล์ Excel ฉบับที่ถูกคอนเฟิร์มล่าสุด

- **US-4.2** ในฐานะ ฝ่ายคลังยา รพ.แม่ข่าย ฉันต้องการรับไฟล์ Excel คำขอเบิกที่มีรูปแบบตรงกับที่ INVC นำเข้าได้ เพื่อไม่ต้องคีย์ข้อมูลซ้ำก่อนตัดคลัง
  - `[รูปแบบคอลัมน์ที่ INVC รองรับ รอยืนยัน — ดู FR-4.3]`

## คำถามที่ถามและคำตอบที่ได้ (Clarifications)

- **ถาม:** รพ.สต. ในเครือข่ายใช้ระบบอะไร, รพ.แม่ข่ายใช้ระบบอะไร? → **ตอบ:** รพ.สต. 29 แห่งใช้ JHCIS และ myPCU (ทั้งสองระบบ); รพ.แม่ข่ายใช้ INVC (ไม่ใช่ HOSxP, ไม่เชื่อม HIS หลักกับ INVC)
- **ถาม:** ต้องการรูปแบบการเชื่อมต่อแบบใด? → **ตอบ:** นำเข้า/ส่งออกไฟล์ (Manual batch) — ระบบคำนวณยอดเบิก → generate Excel อัตโนมัติ → ส่งให้ รพศ. → ฝ่ายคลังยานำเข้า INVC เองเพื่อตัดคลัง
- **ถาม (20260816):** ขั้นตอน "กดปุ่ม → คำนวณอัตโนมัติ → ไฟล์ Excel" เกิดขึ้นตอนไหนเทียบกับ flow ที่มีอยู่? → **ตอบ:** หลังอนุมัติครบ 2 ระดับ แต่คนที่กด "คอนเฟิร์ม" ส่งไฟล์จริงคือเภสัชกรผู้อนุมัติระดับ 2 ไม่ใช่ จนท. รพ.สต.
- **ถาม (20260816):** ไฟล์ที่ส่งเข้าอีเมล + LINE OA ส่งไปหาใคร? → **ตอบ:** ฝ่ายคลังยา รพ.แม่ข่าย (ตาม FR-4.2 เดิม) — **ช่องทางนี้ resolved แล้ว**
- **ถาม (20260816):** กดดาวน์โหลดกับกดคอนเฟิร์มเป็นคนเดียวกันหรือคนละขั้นตอน? → **ตอบ:** จนท. รพ.สต. เป็นผู้ดาวน์โหลด แต่ต้องรอเภสัชกรกดคอนเฟิร์มก่อนเท่านั้นถึงจะดาวน์โหลดได้ (ไม่ใช่ดาวน์โหลดได้อิสระ)
- **ถาม (20260816):** กดคอนเฟิร์มควรทำให้สถานะเป็น "จ่ายแล้ว" ทันทีหรือไม่? → **ตอบ:** ใช่ ทันที ไม่ต้องรอ INVC ยืนยันกลับ

## สิ่งที่ยังไม่ยืนยัน (Open Items)

- **[บล็อกการพัฒนา]** รูปแบบคอลัมน์ไฟล์ที่ INVC รองรับการนำเข้า (FR-4.3) — ควรติดต่อฝ่ายดูแล INVC เพื่อขอรูปแบบให้เร็วที่สุด
- ยืนยันว่าเฟสนี้ไม่ต้องเชื่อมต่อกับ JHCIS/myPCU โดยตรงเลยจริงหรือไม่ (FR-4.4)

## เพิ่มเติม 20260816: แยกบทบาท "คอนเฟิร์ม" (เภสัชกร) กับ "ดาวน์โหลด" (จนท. รพ.สต.)

ผู้ใช้อธิบาย raw requirement เพิ่มเติมว่าต้องการให้ จนท. รพ.สต. กดปุ่มแล้วระบบคำนวณ/ออกไฟล์ Excel ให้ดาวน์โหลดได้ พร้อมส่งอีเมล + LINE OA เมื่อกดคอนเฟิร์ม — หลังตรวจสอบกับ flow เดิม (อนุมัติ 2 ระดับ → พร้อมส่งออก → export) พบว่าทับซ้อนกับ FR-4.1/FR-4.2 เดิม จึงถามยืนยันแทนที่จะเดา ผลคือ: **แก้ FR-4.1 ให้เภสัชกรระดับ 2 เป็นผู้กดคอนเฟิร์ม (สร้างไฟล์ + ส่งอีเมล/LINE + เปลี่ยนสถานะเป็นจ่ายแล้ว), เพิ่ม FR-4.1b ให้ จนท. รพ.สต. ดาวน์โหลดไฟล์เดียวกันได้เฉพาะหลังคอนเฟิร์มแล้ว, และ resolve FR-4.2 (ช่องทาง = อีเมล + LINE OA)** — เดิม FR-4.1 เขียนว่าเภสัชกร/Admin เป็นผู้กดปุ่มสร้างไฟล์เพียงคนเดียว ไม่มีการแยกขั้นตอนดาวน์โหลดของ จนท. รพ.สต.
